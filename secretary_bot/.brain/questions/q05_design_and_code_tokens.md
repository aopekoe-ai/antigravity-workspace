# Q05: デザイントークン・UI余白階層・コード実装規約

## 自問すべきコアの問い
1. **既存システムとの調和**: 新規コンポーネントを勝手に乱造せず、プロジェクト内の既存トークン・共通UI部品を再利用しているか？
2. **視覚ノイズの排除**: 意味のない装飾グラデーション、過剰なドロップシャドウ、バラバラな角丸・余白（マジックナンバー）が混入していないか？

## 実装ガードレール（標準基準・プロジェクト固有値は `DECISIONS_SNAPSHOT.md` 優先）
- **カラー規約**:
  - コンポーネント内に生のカラーコード（`#1a2b3c` 等）を直書きせず、セマンティックトークン（CSS変数 / Tailwindテーマクラス）を使用する。
  - 強いアクセント色は Primary アクションと重要状態バッジのみに絞り、画面面積の85%以上はニュートラルトーンで構成する。
- **タイポグラフィ ＆ 余白リズム**:
  - 余白は 4px / 8px 倍数スケールに統一し、「要素内の余白 ＜ 要素間の余白 ＜ セクション間の余白」の大小関係を厳守する。
  - 数値列・金額・日時は桁揃え（`tabular-nums`）を適用し比較しやすくする。
- **コード・型安全性**:
  - `any` 型や無意味な型アサーションを禁止し、状態遷移は判別可能な Union 型等で表現する。
  - アイコン単独ボタンには必ず `aria-label`、画像には適切な `alt` を付与する。
