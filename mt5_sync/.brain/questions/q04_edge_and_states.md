# Q04: エッジケース・状態遷移・マイクロインタラクション基準

## 自問すべきコアの問い（実装漏れゼロの5状態チェック）
ハッピーパス（理想的なデータが3件入っている状態）だけで作って終わりにしない。必ず以下の5状態を設計・実装すること。

1. **Empty（0件・初期状態）**:
   - ただ「データがありません」と出すのではなく、「なぜ空なのか」＋「最初の1件を作るPrimary導線（またはフィルタ解除ボタン）」を添える。
2. **Loading / Optimistic（読込・処理中）**:
   - ガタつき（CLS）を防ぐスケルトンまたはスピナーを表示し、送信ボタンは処理中に `disabled` ＋ 進行中ラベルに変えて**二重送信を確実に防止**する。
3. **Overflow / Extreme Values（極端な値）**:
   - 名前が60文字、数値が0または1億、テキストが改行付き長文でもレイアウトが崩れない（`truncate` / `line-clamp` / `min-w-0` の適切な適用）。
4. **Error & Recovery（異常系と復帰導線）**:
   - 「エラーが発生しました」だけでなく、「何が原因で、ユーザーはどう直せばよいか（再試行・入力箇所へのフォーカス）」を明示する。
5. **Destructive Action（破壊的操作の安全装置）**:
   - 削除・退会・課金確定などの不可逆操作は、通常ボタンと明確に視覚分離し、影響範囲を伝えた上で確認ステップを挟む。
